# Sub-Store 自用脚本

当前维护的脚本集中在 `V2/`：先处理节点，再生成 mihomo 配置，并按各家机场的节点域名恢复专属 DNS。

| 脚本 | 添加位置 | 用途 |
| --- | --- | --- |
| [节点过滤](V2/节点过滤.js) | 单条订阅的节点操作 | 移除流量、到期和联系方式等说明项 |
| [节点中文化](V2/节点中文化.js) | 单条订阅的节点操作 | 统一国家、地区和城市名称，修正旗帜 |
| [节点排序](V2/节点排序.js) | 单条订阅的节点操作 | 按类型、倍率、地区和名称稳定排序 |
| [订阅 DNS 合并](V2/订阅DNS合并.js) | 文件的脚本操作 | 从原订阅恢复对应节点的专属 DNS |
| [自用覆写 v3](V2/自用覆写v3.js) | 文件的脚本操作 | 生成策略组、规则集、规则和分流 DNS |

## 使用顺序

1. 在单条订阅中按需添加「节点过滤 → 节点中文化 → 节点排序」。
2. 多家机场可通过组合订阅合并，单条订阅中的节点脚本仍会生效。
3. 新建「mihomo 配置文件」，来源选择处理后的单条订阅或组合订阅。
4. 文件操作依次添加「订阅 DNS 合并 → 自用覆写 v3」。
5. 预览输出，核对 `dns.proxy-server-nameserver-policy` 中各家节点域名与 DNS 的对应关系。

脚本操作可粘贴文件全文，也可使用对应脚本的 GitHub Raw 链接。当前 `V2/` 文件路径保持稳定。

DNS 合并依赖原订阅提供含 DNS 的 Clash/mihomo 配置，以及 Sub-Store 后端支持 `includeRaw`。同一节点域名对应不同 DNS 时会报错；节点脚本改写 `server` 后无法自动溯源的情况会给出提示。具体设置见 [订阅 DNS 合并说明](V2/订阅DNS合并说明.md)。

v3 默认使用 `dnsMode: "managed"`、`preservePrivateDns: true`。仅打开保留开关不能恢复转换阶段已经丢失的原 DNS，需要先运行 DNS 合并脚本。

## 本地验证

直接在 Sub-Store 中使用脚本无需安装 npm 依赖。维护公开测试时，在仓库根目录执行：

```sh
npm ci
npm test
```

需要 Node.js 18 或以上版本。测试使用合成节点与模拟的原文接口，不调用真实机场订阅，不连接或测速代理节点；测试通过不等于已验证实际后端和 DNS 服务的连通性。

原始订阅、个人入口替换配置、本机设置及真实节点样例保留在本地，不包含在公开仓库中。
